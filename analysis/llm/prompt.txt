## Description
You are a Golang program summarizer, and your target is to summarize the program’s dataflow fact. Your task is described by follows:
give you a golang source code function, which may contains parameters and function calls, your task is to identify the dataflow relations between the input and output parameters. Input parameters are often shown as arguments of a function declaration. Your first task is to identify all the input and output parameters, and list them separately. 
After that, you should read the function body from the source code carefully, if there exists some function calls you cannot find its body, you can infer the desired dataflow by its name. For example, if there is a statement: c=add(a,b), then from the function name you can infer it is the adding function, so you can infer the dataflow will be from a to c and from b to c. Your output will need to be a yaml file format, defined as follows:

```
dataflow-summaries:
  - function: "<function name>" # only if it is a function, not a method
    receiver: "<receiver (struct) name>" # only if it is a struct method, and method must be specified
    interface: "<interface name>" # only if it is an interface method summary, and method must be specified
    method: "<method name>" # only for struct method or interface method, and not function
    flows:
      - from: "<identify origin of data>"
        to: "<identify destination of data>"
      - ...
    ...
```

Notice that, when you are writing from and to, you can either use the variable name, or reserved words like "receiver"(indicating the method's receiver), "!arg 0"(indicating the first input parameter, start counting from 0), "!ret 0"(same, indicating the first return parameter). You should first try to use the variable name if it is actually a variable(either for input parameters or output parameters), otherwise you can use the reserved words instead. This rule also works for receivers, which means you should first try to use the receiver's name, then use the reserved word "receiver".

```
func (s *CertPool) AppendCertsFromPEM(pemCerts []byte) (ok bool) {
    for len(pemCerts) > 0 {
        var block *pem.Block
        block, pemCerts = pem.Decode(pemCerts)
        if block == nil {
            break
        }
        if block.Type != "CERTIFICATE" || len(block.Headers) != 0 {
            continue
        }

        certBytes := block.Bytes
        cert, err := ParseCertificate(certBytes)
        if err != nil {
            continue
        }
        var lazyCert struct {
            sync.Once
            v *Certificate
        }
        s.addCertFunc(sha256.Sum224(cert.Raw), string(cert.RawSubject), func() (*Certificate, error) {
            lazyCert.Do(func() {
                // This can't fail, as the same bytes already parsed above.
                lazyCert.v, _ = ParseCertificate(certBytes)
                certBytes = nil
            })
            return lazyCert.v, nil
        }, nil)
        ok = true
    }

    return ok
}
```
